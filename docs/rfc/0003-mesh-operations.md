# RFC 0003: Операции над мешем — топология, нож, слияние, пикинг

- Статус: implemented (2026-10-29 … 2026-10-31)
- Автор: агент (по решению владельца)
- Дата: 2026-10-29
- Влияет на: `mesh_ops/*`, `editor/mb_picking.gd`, `editor/mb_selection*.gd`, `editor/mb_toolbar.gd`,
  `meshbuilder_plugin.gd`, `docs/README.ru.md`, `docs/README.en.md`
- Выделено из RFC 0030 «MeshBuilder — редактор пропов на базе PoiBuilder» (разбит на RFC 0001–0007, 2026-11-09)

## Что решили

Набор операций апстрима переработан под моделинг пропов: добавлены Tunnel и Fill по вершинам, убран Collapse,
нож доведён до рабочего состояния на нескольких гранях, добавлено слияние вершин по дистанции. Все операции —
через снапшот данных меша (`MBCommand.copy_mesh_data`) и один шаг `UndoRedo`.

## Операции

### Tunnel вместо Collapse (2026-10-29)

Выделяются две грани в граничном режиме (например, две противоположные стороны коробки), обе удаляются, их
контуры соединяются стенами — получается сквозная дыра в теле. Форма дыры — как были грани: у обеих должно быть
одинаковое число углов (4 и 4, 3 и 3). Стены смотрят внутрь тоннеля, материал и UV берутся с первой грани.
Соседние грани (с общим ребром) отвергаются — тоннель идёт между разными сторонами тела. `Collapse` убран: его
роль закрывает Tunnel.

### Subdivide и Fill (2026-10-29)

`Subdivide` (`D`) в граничном режиме режет квад на 4; в рёберном — делит выделенные рёбра пополам и вставляет
вершины в соседние грани (они становятся n-гонами). `Fill` в вершинном режиме строит грань по 3+ выделенным
вершинам; без выделения закрывает открытые границы меша.

### Нож (2026-10-30)

Режет грань по кликам, включается и из Object-режима (первый клик по грани задаёт её), повторное нажатие —
отмена, `Enter` — разрез. Магнит считается от размера целевой грани, точки разреза ставятся точные (не «по
пикселю»): 14 % самой длинной стороны грани на углы и 20 % на рёбра, зажато в 4 мм…1 м и 6 мм…1.5 м — липнет
одинаково и на пропе в 0.2 м, и на стене в 20 м; `Alt` отключает магнит, пока зажат. Открытый разрез сам продлевается до границы грани. Линия, прошедшая по
нескольким видимым граням, режет все их за один раз (сквозь тело нож не бьёт: задняя стенка не режется, на
стыке остаётся одна вершина). Подсветка выделения при работе ножа больше не глушится.

### Merge by Distance (2026-10-29)

Кнопка `Merge by Dist` в третьем ряду тулбара: `MBMeshOps.merge_by_distance(mesh_data, 0.001)` сливает все пары
вершин ближе 1 мм в одну (как `Merge by Distance` в Blender), грани, потерявшие площадь, удаляются. Работает по
всему мешу, без выделения; undo — общим путём `CmdMeshOp`. Важно про счётчик: копии вершин на гранях
(позиционная приватность) — это НЕ дубли, поэтому `merged` считает только кластеры с РАЗНЫМИ точками (чистый
куб даёт 0, а не 16). Проверки: куб с углом, сдвинутым на 0.4 мм — групп 9 → 8, `merged=1`; чистый куб —
`merged=0` + подсказка «nothing closer than 1 mm»; схлопнутая грань — 2 слияния и 1 удалённая грань (меш
остаётся без переиспользованных рёбер).

### CSG-булевы

Union / subtract / intersect идут через ядро CSG Godot (подробности поведения и грабли — в скилле проекта).
Ядро работает треугольниками, поэтому после булева плагин собирает квады обратно: на сторонах, которых рез не
касался, снова квады, а реально нарезанные места остаются такими, какими их выдало ядро.

## Пикинг и X-Ray: скрытые элементы (2026-10-29)

**Ребра на обратной стороне выбирались при выключенном X-Ray.** `MBPicking.pick_edge` работал двухъярусным:
сначала видимые кандидаты, а если их нет — «фолбэк» на скрытые (унаследованный grab-through-the-mesh из
ProBuilder). Из-за этого клик, ближайшее ВИДИМОЕ ребро которого было на пару пикселей дальше, забирал ребро с
обратной стороны модели. Сейчас при `include_hidden == false` остаётся только ярус видимых (`tiers = [false]`);
скрытые элементы доступны лишь в X-Ray. Замер (куб, камера в 3/4, 8560 точек экрана): до правки 1116
попаданий, из них **137 скрытых**; после — 979 попаданий, **0 скрытых**; в X-Ray 184 скрытых попадания (режим
работает). Вершины (`pick_vertex`) при `xray = false` тоже дают скрытые попадания — 68 из 621 замера —
оставлены как есть до решения владельца.

## Грабли реализации

### Bevel и грань с вырезом

`cut_face` с замкнутым контуром хранит грань с дырой как ОДИН «сшитый» полигон, который проходит через угол
шва дважды; bevel строит фаску по контурам граней и на таком контуре либо падал (`a face touches the same
corner twice`), либо ломался на рёбрах-рейлах. Решение: перед построением фаски `MBBevel._heal_spliced_faces()`
разрезает только затронутые выделением сшитые грани на треугольники (дыра остаётся дырой, меняется лишь
топология заплатки), после чего номера выделенных рёбер пересчитываются по координатам концов
(`_resolve_edge_ids` — как раз потому, что новые грани сдвигают индексы). Проверено: куб с вырезом 5×5 см на
верхней грани, ребро внешнего контура — 7 → 18 граней, 0 открытых и 0 переиспользованных рёбер; с 3 сегментами
— 19 граней.

### Торцы фаски при сегментах > 2 были n-гонами

Конец полосы бейвела закрывался одной гранью, у которой число углов растёт с сегментами: 2 сегмента —
треугольник, 3 — четырёхугольник, 4 — пятиугольник, 5 — шестиугольник (`_face_from_indices`/`_fan_cap` отдавали
один полигон). Теперь при 4+ точках кольца торец раскладывается на **отдельные треугольники** веером из
центроида (`_fan_cap_triangles`): геометрия та же (площадь не изменилась: 5.9217 при 3 сегментах до и после),
топология — только треугольники. Замеры на кубе, одно ребро: seg=2 → 2 треугольника, seg=3 → 8 (4 на торец),
seg=4 → 10, seg=5 → 12; меш замкнут (0 открытых, 0 переиспользованных рёбер) во всех случаях. Угловые
«купола» (2+ бейвеленных ребра в вершине) остаются куполами — у них своя ветка `_build_cap_dome`.

### Bevel вершины: границы и лишний слайдер

Вершина на открытой кромке (лестница, половина меша) срезалась с дырой в меше — теперь `bevel_vertices`
считает грани на ребро для каждой вершины (пересчёт на каждую, потому что предыдущий бейвел перестраивает
топологию) и вершины на открытой кромке **пропускает**, а если других нет — отвечает `the selected vertex sits
on an open border`. У вершинного бейвела нет сегментов (это один плоский срез), поэтому слайдер `Segments` в
модалке для вершин **не показывается** — раньше он был и ничего не делал. Проверено: куб — вершина 7 граней,
все 8 вершин 14, две соседние 8; лестница — отказ, меш не тронут; сфера/цилиндр/конус/призма — без открытых и
вывернутых граней.

### Вершинный бейвел ломал UV двумя способами

(1) Точки среза были ОДНОЙ копией на все грани, поэтому `MBUv.apply_face_uvs` каждой грани перезаписывал общий
слот `textures0` — после бейвела 3 из 7 граней имели растяжение UV до 7×. Лечение: позиционная приватность как
в рёберном бейвеле (`_cut_position(..., owner = fi)`), кольцо торца дедуплицируется **по координате**, свои
копии угловой грани создаются через `_dup_position_at`, а `_rebuild_topology` сваривает совпадающие копии
обратно (иначе кольцо получает по две одинаковые точки на каждую грань и в грани появляются self-edges).
(2) Пересобранные грани создавались «с нуля» и **теряли настройки UV** (`uv_scale`/`uv_rotation`/`uv_offset`/
флипы/`texture_group`/`element_group`): при тайлинге 2× и повороте 30° четыре грани возвращались с 1×1 и 0°.
Лечение: `_copy_face_uv_props(orig, rebuilt)` + повторный `apply_face_uvs`; угловая грань наследует настройки
первой инцидентной. Проверено: битых авто-UV 0 из 7 (было 3), потерявших тайлинг 0 (было 4), меш замкнут
(0 открытых рёбер), эталонный рёберный бейвел не изменился.

## Открытые вопросы

- **Кромка выреза не бейвелится** («cannot bevel open boundary or coplanar edges»): у отверстия нет стенок,
  ребро граничит с одной гранью — сначала вырез нужно прорезать насквозь или выдавить внутрь.
- Вершины при выключенном X-Ray дают попадания по скрытым точкам (рёбра уже отфильтрованы, вершины — нет) —
  оставлено до решения владельца.
