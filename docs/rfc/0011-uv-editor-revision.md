# RFC 0011: Ревизия UV-редактора

- Статус: draft
- Автор: владелец (записано агентом 2026-11-09)
- Дата: 2026-11-09
- Влияет на: `editor/uv/*` (`mb_uv_editor_panel.gd`, `mb_uv_canvas.gd`, `mb_uv_ops.gd`, `mb_uv_gizmo.gd`),
  `core/mb_uv.gd`, `core/mb_mesh_data.gd`, `editor/mb_actions.gd` (бинды UV), `docs/README.ru.md`,
  `docs/README.en.md`, `dist/listing.md` (отдельный гейт — правится по отдельной команде)

## Что решили (черновик)

UV-редактор достался от апстрима целиком и с тех пор не пересматривался: кнопок много, часть, скорее всего,
не нужна, а нужного, вероятно, не хватает. Решение: провести ревизию — пройти по каждому органу управления,
снять «нужно / не нужно / не работает / не хватает» — и после этого доработать редактор под реальные задачи
(пропы для города: модульные стены, крыши, окна, тайлинг текстур). Ревизия — отдельный проход с владельцем у
экрана, а не «угадать по коду».

Плагин для журнала «моделирование», поэтому цель ревизии — не паритет с ProBuilder, а минимальный рабочий
UV-редактор: разложить тайл, выровнять по сетке, поправить офсет/угол грани, сшить шов, развернуть грань под
текстуру.

## Текущий инвентарь (по коду `editor/uv/mb_uv_editor_panel.gd`, 2026-11-09)

Четыре строки тулбара, ~40 органов управления плюс сам 2D-canvas.

**Строка 1 — инструменты и навигация.** Move / Rotate / Scale (W/E/R); режимы выбора Face / Vertex / Edge /
Island; Frame `[0,1]` и `⛶ Frame` (F); переключатель канала UV1 (Texture) / UV2 (Lightmap); статус-строка
«Mode: … | N selected»; кнопка «↗ Window» (pop-out во плавающее окно).

**Строка 2 — сетка, текстура, texel density.** Snap + шаг сетки (1/32 … 1.0); Texture (подложка материала);
Tile (повтор подложки); Opacity (ползунок 0…1); Texel: Get / спинбокс px/m / Set.

**Строка 3 — операции.** Auto / Manual (перевод режима UV граней); проекции Planar / Box / Fit / Unwrap /
Lightmap (UV2 под LightmapGI, по всему мешу); Flip U / Flip V; `↶ 90°` / `↷ 90°`; Sew / Split / Collapse /
Stitch; Export PNG (шаблон развёртки).

**Строка 4 — «Face:» процедурные параметры грани.** `x2` / `÷2` / `Reset (1m)` / `45°`; Tiling U, Tiling V;
Offset U, Offset V; Angle; чекбоксы Flip U / Flip V; Tint (ColorPickerButton) + White.

## Что проверить (гипотезы, не решения)

- **Одинаковые на вид пары.** `Flip U`/`Flip V` есть дважды: в строке 3 — это переворот UV выделения
  (`MBUvOps.flip_uvs`), в строке 4 — процедурный `uv_flip_*` грани. Пользователь видит две пары с одним
  названием. Так же `x2`/`÷2`/`45°`/`Reset` в строке 4 дублируют спинбоксы тайлинга/угла рядом. Надо решить:
  объединить, переименовать или оставить (одно — через UV-координаты, другое — через поле грани).
- **Texel density.** Get / Set / px/m — нужна ли вообще в пропах, где тайлинг задаётся полем грани, а не
  масштабом UV? Проверить на реальной стене.
- **UV2 / Lightmap.** Узкая функция под `LightmapGI`; в городских пропах лайтмапа, вероятно, не применяется.
  Не удалять вслепую (умение дорогое), но проверить, не ломает ли она основной сценарий.
- **Unwrap vs Box.** `unwrap_box` против `box_project` — оценить, что реально делает каждый на составной
  фигуре и не проще ли оставить один.
- **Острова и швы (Sew / Split / Collapse / Stitch, режим Island).** Самые рискованные: UV-связность живёт на
  дублях позиций (позиция на каждую грань, `shared_textures`), а не на индексах — проверить каждую операцию
  на шве из двух граней и на меше после extrude/knife.
- **Pop-out окно.** Проверить переживание переключения вкладок и потери выделения.
- **Snap / Island / Frame.** Проверить, что бинды в `editor/mb_actions.gd` соответствуют кнопкам и что
  подсказки инструментов не врут.

## Чего вероятно не хватает (кандидаты, обсуждаются)

- нормальная авторазвёртка (не box-раскладка) для сложных фигур;
- упаковка островов в атлас (и проверка перекрытий островов/пикселей);
- выравнивание UV по осям и по выделению (align / straighten), копирование UV одной грани на другую;
- работа с несколькими мешами сразу (сейчас всё идёт через `active_mesh`);
- предсказуемый undo на каждое действие строки «Face:» (сейчас — по факту `_execute_uv_op`).

## Последствия

- Ревизия может вырезать органы управления — это меняет документацию (`docs/README.ru.md` → EN) и листинг
  стора (`dist/listing.md` правится отдельным гейтом, по отдельной команде).
- Кнопки UV не описаны в `AGENTS.md`-правиле «четыре точки правки» (это правило про операции меша) — при
  добавлении новых UV-операций придерживаться той же схемы: `MBUvOps` → кнопка в панели → undo через
  `_execute_uv_op` → строка в 문서х.

## Открытые вопросы

- какая часть строки «Face:» (тайлинг/офсет/угол/флипы/тинт) остаётся в UV-редакторе, а какая должна жить
  в палитре материалов;
- нужен ли UV2 в плагине вообще;
- какая конечная цель редактора — «разложить один тайл аккуратно» или полноценный unwrap под атлас.

## Проверка (когда будет код)

- пройти тулбар строка за строкой на тестовом меше (стена, крыша, окно) и составить список «мёртвых» кнопок;
- каждая оставленная операция — один шаг undo и запись в статус-строке;
- грепом по старым именам в `docs/*` и `README.md` — ноль.
